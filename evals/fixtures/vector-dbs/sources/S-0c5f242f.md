# Explorer tool

The Explorer tool is a graphical interface for working with the data in a Weaviate Cloud cluster. Browse collections, examine objects, inspect metadata and vectors, and run keyword, semantic, hybrid, and aggregation searches, all without writing a query.

The Query tool was removed from the Weaviate Cloud console on **September 14, 2026**. Nothing changes for your clusters. This is console tooling only, so they keep running exactly as they are, with no downtime and nothing you need to do on your end.

The Explorer tool covers the everyday Query tool tasks without writing a query: keyword, semantic, and hybrid search, aggregations, filters, and inference keys. For anything beyond that, use a client library to query your data from your application code.

## Open the Explorer tool​

The Explorer tool is available for collections that are hosted in Weaviate Cloud.

`Explorer`

If you don't see any available clusters, select the `Clusters` option from the left sidebar and follow the steps to create a new cluster.

`Clusters`

To review how the collection itself is configured, click the `View collection details` button in the page header.

`View collection details`

## Search and explore​

The `Search & explore` panel sits above the results and has five modes:

`Search & explore`

| Mode | What it does |
| --- | --- |
| `Browse` | Lists the objects in the collection, page by page. |
| `Hybrid` | Blends keyword and vector search in a single search. |
| `Semantic` | Ranks objects by meaning, from a description or from a vector. |
| `Keyword` | Ranks objects by keyword relevance. |
| `Aggregate` | Calculates a metric over the collection instead of returning objects. |

`Browse`
`Hybrid`
`Semantic`
`Keyword`
`Aggregate`

### Browse​

`Browse` mode lists the objects in the collection. Each object is shown with its:

`Browse`

Some details are initially collapsed. Click a color-coded property group, such as metadata or vectors, to expand it and view the details. Hover over a property name to see the property type.

Vectors are shown initially by name, where named vectors are used, and by their number of dimensions. Expand the entry to see part of the vector, or click `copy` to copy the entire vector to your clipboard.

`copy`

Pagination controls at the bottom of the list step through the objects. A dropdown next to them sets the number of objects per page and shows the total number of objects in the collection. The refresh button at the top of the page reloads the list.

### Hybrid search​

`Hybrid` mode blends keyword and vector search in a single search, so an object can rank highly because it matches your search terms, because it matches your meaning, or both. For each half on its own, see semantic search and keyword search.

`Hybrid`

Search with either of:

`Text`
`Vector`

Use the `in:` selector to choose which properties are searched.

`in:`

Under `Advanced options`, the `Keyword ↔ vector balance (alpha)` slider sets how much each half of the search contributes. In the Explorer tool the slider starts at `0.5`, which weights the keyword and vector components equally. See the alpha parameter for what the value means.

`Advanced options`
`Keyword ↔ vector balance (alpha)`
`0.5`

If the panel asks for a model provider key, see inference keys.

For the equivalent query in application code, see hybrid search.

### Semantic search​

`Semantic` mode ranks results by meaning rather than by exact words, so a relevant object can rank highly even if it shares no words with your search.

`Semantic`

Search with either of:

`Text`
`Vector`

If the panel asks for a model provider key, see inference keys.

For the equivalent query in application code, see vector similarity search, and for the underlying idea, see vector search.

### Keyword search​

`Keyword` mode ranks results by BM25 relevance, so the objects that match your search terms most strongly come first.

`Keyword`

A keyword search reads every property by default. To narrow it, use the `in:` selector to choose which properties are searched.

`in:`

For the equivalent query in application code, see keyword search.

### Aggregate​

`Aggregate` mode calculates a metric over the collection instead of returning objects. The controls read as a sentence: `Show <metric> of <target> grouped by <property>`.

`Aggregate`
`Show <metric> of <target> grouped by <property>`
`Count`
`Minimum`
`Maximum`
`Mean`
`Median`
`Mode`
`Sum`

Click `Calculate` to run the aggregation.

`Calculate`

For the equivalent query in application code, see aggregate.

## Filter and sort​

Filters are available in every mode, including `Browse`. Click `Add condition` to build a filter condition, then click `Apply` to run it.

`Browse`
`Add condition`
`Apply`

Sorting is available in `Browse` only. `Browse` offers a `Filter & Sort` control, while the search modes offer `Filter` alone, since those modes order the results by relevance.

`Browse`
`Filter & Sort`
`Filter`

## Inference keys​

`Semantic` and `Hybrid` searches vectorize your search text with the model provider that the collection is configured to use. Where that provider needs an API key, the `Search & explore` panel prompts you for one before the search runs.

`Semantic`
`Hybrid`
`Search & explore`

Enter the key in the panel. The field is named for that provider, for example `OpenAI API key`, and the key is used for this search only and never stored.

`OpenAI API key`
